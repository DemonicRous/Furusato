# Lime Core 0.2.0

Версия 0.2.0 делает Unicode GUI Scale patch управляемым, диагностируемым и
безопасным при изменении ожидаемой структуры bytecode Minecraft.

## Основные нововведения

### Ранняя конфигурация CoreMod

Lime Core теперь загружает настройки на стадии `IFMLLoadingPlugin.injectData()`,
до обычной инициализации Forge-модов. Это позволяет управлять bytecode-патчами
до загрузки целевых классов Minecraft.

При первом запуске автоматически создаётся файл:

```text
config/limecore.properties
```

Его стандартное содержимое:

```properties
patches.unicodeGuiScale=true
diagnostics.logging=true
```

- `patches.unicodeGuiScale` включает или отключает сохранение нечётного
  масштаба интерфейса при использовании Unicode-шрифта.
- `diagnostics.logging` управляет выводом диагностической сводки Lime Core.

После изменения файла необходим полный перезапуск клиента.

### Управляемый Unicode GUI Scale patch

При включённом патче выбранный нечётный масштаб интерфейса больше не
уменьшается Minecraft из-за активного Unicode-шрифта. Например, при русском
языке GUI Scale 3 остаётся равным 3, а не переключается на 2.

Если параметр `patches.unicodeGuiScale` установлен в `false`, Lime Core оставляет
`ScaledResolution` без изменений и регистрирует отключённое состояние в журнале.

## Безопасность ASM-преобразования

Сопоставление bytecode стало строже. Перед изменением проверяются:

- целевой класс `net.minecraft.client.gui.ScaledResolution`;
- obfuscated-имя класса `bit`;
- конструктор целевого класса;
- владелец вызова `net.minecraft.client.Minecraft` или `bib`;
- инструкция `INVOKEVIRTUAL`;
- сигнатура метода `()Z`;
- имена `isUnicode`, `func_152349_b` и `e`;
- точное количество совпадений — должен быть найден ровно один вызов.

Если структура класса не соответствует ожидаемой, Lime Core возвращает
исходный bytecode. Игра продолжает запуск без патча вместо применения
потенциально опасного преобразования.

Также исправлено obfuscated-имя `ScaledResolution`: в версии 0.1.0 использовалось
`bip`, которое на самом деле принадлежит `FontRenderer`. Корректное имя для
Minecraft 1.12.2 — `bit`.

## Диагностика

Lime Core отслеживает следующие состояния патча:

- `REGISTERED` — трансформер зарегистрирован и ожидает целевой класс;
- `APPLIED` — bytecode успешно изменён;
- `DISABLED` — патч отключён конфигурацией;
- `SKIPPED` — ожидаемая структура класса не найдена;
- `FAILED` — во время преобразования произошла ошибка.

Примеры сообщений журнала:

```text
[Lime Core/Config]: Loaded early configuration from .../config/limecore.properties
[Lime Core/ASM]: Preserved odd Unicode GUI scales
[Lime Core/ASM]: Unicode GUI-scale patch is disabled
```

Состояние `REGISTERED` в ранней сводке означает, что к моменту её вывода
`ScaledResolution` ещё не был загружен. Фактический итог применения фиксируется
более поздним сообщением категории `Lime Core/ASM`.

## Тестирование и сборка

Добавлены тесты для следующих сценариев:

- успешная замена Unicode-проверки;
- сохранение корректного состояния operand stack;
- отключённый патч;
- отклонение вызова с неожиданным owner;
- создание конфигурации со стандартными значениями;
- чтение пользовательских настроек до инициализации мода.

Репозиторий теперь содержит GitHub Actions workflow, который собирает проект и
запускает тесты на JDK 8. Локально версия проверяется командой:

```powershell
.\gradlew.bat clean build
```

Готовые файлы создаются в `build/libs`:

```text
LimeCore-0.2.0.jar
LimeCore-0.2.0-sources.jar
```

## Проверенная среда

- Minecraft 1.12.2;
- Minecraft Forge 14.23.5.2847;
- JDK 8;
- русский язык;
- GUI Scale 3;
- включённый и отключённый Unicode GUI Scale patch.

## Обновление с 0.1.0

1. Замените старый JAR на `LimeCore-0.2.0.jar`.
2. Запустите клиент один раз для создания `config/limecore.properties`.
3. Проверьте нужное значение `patches.unicodeGuiScale`.
4. Полностью перезапустите клиент после изменения конфигурации.

Дополнительная миграция ресурсов или игровых данных не требуется.
